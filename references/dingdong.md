# 叮咚好食光

## 执行预算

详情页文案替换、详情页生成、七图主图生成和最终验证的主动处理目标为 30 分钟以内：

1. 资料提取、模板原文定位和聊天初稿：不超过 5 分钟。
2. 用户定稿后的正式文案校验与详情页生成：不超过 10 分钟。
3. 复用详情页生成七图主图：不超过 10 分钟。
4. 预览、重开、已使用图片归类和最终验证：预留 5 分钟。

用户等待确认、Photoshop 无响应和异常大文件 I/O 单独计时并立即说明。不要为追求形式完整而重复读取资料、渲染文档、制作图片联系表、重建索引或反复生成 JSON。

## 详情页

拟写或替换详情页文案前完整阅读 [dingdong-copy-grammar.md](dingdong-copy-grammar.md)。用户提供目录时，先递归列出文件名，一次性提取相关 Word、表格和文本事实并读取已登记模板索引。只为提取正文和表格时不要额外渲染 Word；只有排版、批注、文本框或嵌入对象可能影响事实时才渲染。只在文档事实不足且某一候选必须依靠图片时查看对应图片，不要默认逐张检查全部图片。普通适配文案不得出现完整二字“入+名词”词组；脚本按 `proposedSegments` 的词组边界在正式审核、任务生成及准备前复验，命中即报错。逐字步骤，以及用户针对当前审核稿明确指定的完整短语或“A 改为 B”精确替换，按合并后的目标全文登记为 `verbatim`，可保留“入味”等用户指定字样；记录用户原话，不得把代理候选伪装成逐字来源。版4普通适配文案不得描述预制或包装状态，也不得复述食用步骤、火候、时长或烹饪操作；分别以 `forbidden-block4-prep-packaging-copy` 或 `forbidden-block4-instruction-copy` 阻断。版6两个说明必须各写一种不同配菜；在 `facts` 中为每种配菜声明 `category: "side-dish"` 和非空 `terms`，对应说明只绑定一种配菜事实且正文命中其词，重复或缺失均阻断。

先在聊天中直接展示固定九列初稿：`版块｜原文｜原语法｜原字数｜新文｜新语法｜新字数｜事实依据｜状态`。一行只能对应一个完整板块；把该板块的标题、上文、下文和说明按 PSD 阅读顺序合并到同一行的原文/新文单元格，使用 `<br>` 表示内部换行。禁止把版4主料标题与口感说明、版6标题与两条说明等拆成独立审核行，正式审核稿也必须使用同样的板块合并方式。标题与下方说明必须分别承担不同信息：先为每段明确外观、口感、风味、配菜、方法、场景或利益点等信息焦点；若上下段落重复同一焦点、使用近义词复述同一卖点，标记 `duplicate-board-copy-focus` 并重写下方说明后再展示。保留逐字步骤和原字号；普通文案使用当前菜品事实并保持原文语法、分句和版式，未登记文字显示“保留不改”。初稿阶段不要创建 `copy.json`、审核文件、联系表或一次性提取脚本。发现“肉末／肉沫”等冲突时，立即在相关行标记阻断并询问，不要先完成整套生产文件。

版6主标题固定以“特调”开头；聊天初稿、正式审核和任务中的该目标都必须遵守，其他开头由脚本以 `required-copy-prefix` 阻断。

版8场景文案固定为两行“下班回家轻松煮”“煮好后热乎上桌”。聊天初稿、正式审核和任务中的该目标必须逐字符一致，写入 Photoshop 时使用 CR 换行并保留末尾 CR；“5分钟热乎上桌”等任何其他文字、行末空格或换行形式由脚本以 `required-exact-copy` 阻断。

### 确认阶段修改与重新生成

1. 从首次展示九列初稿到最终套版完成，用户要求修改、重写、换一种说法或重新生成任一文案时，把本轮需要生成的行重新视为未确认候选。确认阶段的重新生成不是自由润色，必须从模板原文和当前产品事实重新执行与初稿完全相同的规则：先拆原文，再按原语法、分句、版式和字数生成；保留逐字来源；重新核对事实依据、术语决策、版块专属禁写、固定前缀、固定文字和受保护范围；最后以固定九列展示。
2. 只重新生成用户明确点名的行，以及因本次事实、术语或跨行唯一性约束而必须联动的行。未点名行逐字符不变；需要联动时先在状态列写明原因，不得借机重写其他文案。用户直接提供新文字时，也要按同一套规则校验；不合规就标记具体阻断，不得把它伪装成 `verbatim` 或静默改成另一个版本。
3. 每轮修改后重新展示完整九列表作为新的当前审核对象，并在用户再次明确确认前保持在审核阶段。若修改发生在先前已经“确认文案”之后，先前冻结的九列表、正式审核稿、`copy.json`、SHA-256、详情页任务和套版授权全部变为旧版本，禁止继续使用或据此写入 PSD；按新九列表重新确认后，再生成并绑定新版本的正式文件。

用户解决冲突并说“确认文案”“文案确认”“按这个套版”等同义表达后，冻结刚展示的九列表，并只生成一次 `copyVersion: 2` 的 `copy.json`。运行标准脚本生成正式审核稿：

```powershell
.\scripts\new-dingdong-copy-review.ps1 `
  -CopyPath C:\work\copy.json `
  -OutputPath C:\work\copy-review.md
```

比较正式审核稿与用户刚确认的九列表；文字、模式、语法、字数和保留范围必须一致。完全一致且校验通过时，直接使用输出的 SHA-256 生成任务并进入详情页套版，不再向用户索要第二次确认。SHA-256 是内部防篡改绑定，不是新的审批门槛：

```powershell
.\scripts\new-dingdong-detail-job.ps1 `
  -TemplateId dingdong-haoshiguang-detail-3step `
  -CopyPath C:\work\copy.json `
  -ApprovedCopySha256 已确认的SHA256 `
  -TargetPsdPath D:\商品\详情页.psd `
  -OutputPath C:\work\detail-job.json
```

一步版改用 `dingdong-haoshiguang-detail-1step`，两步版改用 `dingdong-haoshiguang-detail-2step`，四步版改用 `dingdong-haoshiguang-detail-4step`。详情页模板的 `protectedTextTargets` 和 `protectedPathPrefixes` 永久只读；不只版2，定义中其他受保护目标也同样禁止修改。任务生成和准备阶段都会重新校验保护范围和确认哈希；失败时不会创建或打开 PSD 工作副本。不得询问是否解锁，不得写入或接受非空 `protectedOverrides`，也不得用手写任务绕过；这些位置由用户自行在 Photoshop 中修改。

用户原请求已经包含详情页文案替换时，“确认文案”授权连续执行：生成正式审核文件、生成任务、准备工作副本、写入文字和导出预览。自行检查预览后按正常两步生产完成 PSD；用户明确说“只看审核稿”或“只做预览”时才停在对应阶段。不得回复“只有确认该哈希后才会生成任务”，也不得询问“是否写入 PSD”。

### 步骤文案遮挡

1. 已确认的逐字步骤始终按全文、原标点和原字号写入。不要为消除遮挡而缩字、删改、改标点、改行距或扩展文本框。
2. 必须查看实际预览；步骤部分或全部被遮挡时，把它记为警告而不是提交阻断。其他验证通过后继续完成 PSD，不询问用户是否改短或是否继续写入。
3. 完成后逐个步骤报告可见性。完整显示时写“步骤 N：全部可见”；存在遮挡时写明预览中的可见终点，并逐字符引用被遮挡的完整原文。
4. 遮挡范围必须来自实际预览，不得只按字数或文本框容量估算。边界字符显示不完整时，把该字符计入被遮挡部分。
5. 文字写入不一致、字号变化、保存失败或重开验证失败仍按硬错误阻断；本规则只把视觉遮挡从提交门槛改为完成后的必报事项。

## 七图主图

收到“制作主图”后，除恢复已经 `prepared` 或 `committed` 的现行主图运行外，第一项生产动作固定为使用当前正式详情 PSD 执行统一入口预检：

```powershell
.\scripts\invoke-dingdong-product.ps1 `
  -TaskDirectory C:\work `
  -ApprovedDetailCopyPath C:\work\copy.json `
  -ApprovedCopySha256 已确认的SHA256 `
  -DetailPsdPath D:\商品\详情页.psd `
  -DetailIndexPath C:\work\detail-index.json `
  -MainTargetPsdPath D:\商品\主图.psd `
  -PrepareMain:$false
```

该调用必须先刷新并检查当前已保存的正式详情 PSD。返回前禁止扫描产品原图、制作选图总览、手工创建直接图片 mapping 或要求用户确认图片映射。`imageChangedCount` 只记录所属任务本次新增或替换的图片数量，不是 PSD 图片清单，永久禁止用它判断正式详情 PSD 当前是否含图。预检成功解析七项唯一来源后，复用同一任务目录再次运行统一入口并按需要传入 `-CommitMain`；任一来源缺失或不唯一时，在打开主图母版前停止并只报告具体版块。只有预检确认正式详情页尚未放图，或用户明确要求使用不同原图时，才进入直接图片模式。

正式详情页是七图主图的默认图片来源。只要正式详情页已经放好图片，就一次索引该 PSD，并按详情页模板定义中的 `mainImageSourceSlots` 自动建立七项 `source` 映射：

1. 画板1取头版主图。
2. 画板2取版2主图。
3. 画板3取最后一个编号步骤的图片。
4. 画板4取版4主图。
5. 画板5取版5主图。
6. 画板6取版6主图，排除文字、标注和装饰叠层。
7. 画板7取版8主场景图。

来源必须是对应底图同组中的实际像素或智能对象图层；优先选择紧邻登记底图、参与该底图剪贴关系且可唯一定位的图片。七项都唯一时直接生成主图，不要求用户再次确认图片映射。不得因为原图文件已知而绕开正式详情页重新选图，也不得因画板1至3看起来正确就允许画板4至7使用自由选图。

任何一个详情页来源缺失或不唯一时，在打开主图母版前停止并只报告具体版块；不得自动回退到相似原图、旧映射或临时详情页。只有正式详情页尚未放图、来源确实无法唯一定位，或用户明确要求主图使用不同图片时，才使用直接图片模式并要求逐项确认。

详情页来源模式禁止手工编写 `mapping.json`。使用 `new-dingdong-main-mapping.ps1` 从已确认详情页文案和正式详情页索引自动生成同步文案及七项来源；日常生产优先直接使用统一入口：

```powershell
.\scripts\invoke-dingdong-product.ps1 `
  -TaskDirectory C:\work `
  -ApprovedDetailCopyPath C:\work\copy.json `
  -ApprovedCopySha256 已确认的SHA256 `
  -DetailPsdPath D:\商品\详情页.psd `
  -DetailIndexPath C:\work\detail-index.json `
  -MainTargetPsdPath D:\商品\主图.psd `
  -CommitMain
```

该入口默认先以 `-DetailPsdPath` 定向刷新详情索引，再直接准备主图；索引时若 PSD 已打开且有未保存修改会停止，未打开时只临时打开该文件并无保存关闭。mapping 缓存同时绑定详情 PSD、详情索引和已确认文案的 SHA-256，任一变化都必须重建，避免把放图前的旧索引用于主图。`-CommitMain` 连续提交、重开验证并马上归类已使用图片。它写入 `dingdong-product-state.json` 和各阶段耗时；已到 `prepared` 或 `committed` 的运行不会重新索引或改写 mapping/job，而由完成校验继续验证来源稳定性。只有测试夹具或明确的离线诊断才使用 `-RefreshDetailIndex:$false`。

只有直接图片模式才手工提供 `mapping.json`。它包含 `textReplacements` 和恰好七项 `imageMappings`，每项提供 `imagePath`、主图底层目标选择器、名称和可选 fit：

```json
{
  "textReplacements": [],
  "imageSelectionApproval": {
      "userInstruction": "确认图片映射，按刚才展示的七画板图片制作",
    "items": [
      { "targetId": 201, "imagePath": "D:/商品/封面.jpg" }
    ]
  },
  "imageMappings": [
    {
      "imagePath": "D:/商品/封面.jpg",
      "target": { "id": 201, "path": "1/图片剪贴蒙版位置" },
      "name": "画板1商品图"
    }
  ]
}
```

画板2全部文字和模式为 `sync-detail-current` 的文字永久只读，不能因用户授权、`protectedOverrides` 或手写任务而解锁。画板3步骤数量标题也保留在 `unchangedTextTargets`，但有且只有一个数字同步例外：从详情定义读取并验证 `currentSteps` 唯一、从 1 连续编号；当模板标题中的步骤数字与现行步骤数不一致时，自动 mapping 只把标题中唯一的 `N步` 数字同步为已登记的 1、2、3 或 4，并标记 `generatedFrom: sync-step-count` 和实际 `stepCount`。数字已经一致时不生成替换；未登记步骤数、元数据缺失、伪造模式、数量不一致或除数字外任一字符变化均以 `invalid-step-count-sync` 阻断。字号、版式和标题其他文字始终不变。生成器和准备脚本都会在 Photoshop 前复验这项窄例外；其他受保护目标仍会快照文字、字号、可见性和路径，并在提交后重开逐项复核。其余主图文案不得重新创作；自动 mapping 必须通过 `approvedDetailCopy.copyPath` 和 `copySha256` 绑定已确认详情页文案，生成器按模板 `sourceDetailIds` 生成并验证同步文案、组合文案和逐字步骤。

运行：

```powershell
.\scripts\new-dingdong-main-job.ps1 `
  -MappingPath C:\work\mapping.json `
  -TargetPsdPath D:\商品\主图.psd `
  -OutputPath C:\work\main-job.json
```

详情页来源模式必须让全部七项 `imageMappings` 使用 `source` 选择器并传入正式详情页的 `-DetailPsdPath`；直接图片模式必须让全部七项使用 `imagePath`，禁止两种来源混用。禁止因为主图生成器需要图片来源而先创建临时详情页、向临时详情页放七张图、再把图片复制到主图。直接图片模式必须先展示七行 `画板｜用途｜图片文件` 映射，并要求用户明确回复“确认图片映射”或语义完全等价的表达后写入 `imageSelectionApproval`；“制作主图”“重新制作主图”“使用新 skill”都只授权开始流程，不等于批准之前或当前由代理自行挑选的七张图片。

详情页来源模式会在主图提交并重开验证后自动整理详情目录实际使用的图片；`-DetailWorkDir` 仅用于覆盖默认的详情页父目录，不需要再传 `-OrganizeUsedAssets`，也不再单独审批或拆成后续任务。整理扫描正式详情页全部可见智能对象，只处理工作目录根层且被实际引用的图片；七项主图来源映射不得作为 `sourceLayerIds` 过滤器。已有同一 PSD 的完成 journal 若使用不同筛选范围，先归档再全量重扫，并在同目录写入新的可恢复 journal。需要最终七张 JPG 时传入 `-FinalOutputDirectory`。

主图完成调用的固定顺序是：提交主图 PSD → 重开验证 → 立即归类详情页已使用图片 → 记录归类结果 → 执行本次要求的其他最终输出。归类失败不回滚已经验证的主图 PSD，但整条叮咚流程必须报告为“主图完成、图片归类失败”，不能省略或延后归类。

主图任务只读取固定主图模板、一次 mapping 及 mapping 明确引用的七张图片；使用 `source` 时额外读取一次已验证详情页。不得重新读取 Word、重新分析全部产品图片、文案语法标注或详情页模板索引。选图确有必要时一次查看缩略图后立即固定七张映射，不反复制作联系表或逐图重审。画板 0 保留；最终输出固定按 1–7 顺序、800px 宽导出。步骤文字不缩写、不改标点、不缩小字号；详情页或主图中的步骤遮挡按“步骤文案遮挡”规范直接完成并报告。

## 整包导出

用户说“导出某路径的图片”时，直接运行 `export-dingdong-image-package.ps1 -ProductDirectory <指定路径>`。只按指定路径根层中当前保存的 PSD 结构识别唯一详情页和主图；不得使用文件名推断。详情页固定导出一张原画布尺寸的 `详情页长图.jpg`，切片只使用该商品详情 PSD 自己保存的有效水平参考线和它当前的画布首尾，禁止读取或回退到母版参考线、模板定义、模板索引、固定切片高度或历史切片记录。整包导出主图必须按名称顺序导出画板 0–7，画板 0 不得排除。商品根层如有唯一的 `白底图` 或 `标签` JPG/JPEG/PNG/WEBP，或精确文件名 `包装图.jpg`、`白标.jpg`，以原字节复制到 `主图/`；同类多文件或不支持格式立即阻断。

把详情页长图与切片、八张主图、可选白底图、标签图、`包装图.jpg`、`白标.jpg`，以及该路径 `已使用` 文件夹中的受支持图片先完整保存到商品目录的 `未压缩图片-yyyyMMdd-HHmmss`。该目录不压缩、不打包；随后只对它的临时 `详情页/` 和 `主图/` 副本调用 `D:\谷鱼视觉\小梅园\images\image-compressor.exe`，`已使用/` 图片保持未压缩，最终在 `D:\谷鱼视觉\小梅园` 生成并验证 7z。源 PSD、原始附件、已使用图片和商品目录内的未压缩输出在压缩阶段必须保持 SHA-256 不变；任何缺项或来源不唯一都立即阻断，不得使用母版或旧导出结果补齐。
